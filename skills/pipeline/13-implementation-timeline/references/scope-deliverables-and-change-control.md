# Scope, Deliverables, and Change Control

Projects succeed when objectives, scope, deliverables, and change control are explicit, and fail when these drift. This reference paraphrases methods from *Mastering Project Management Integration and Scope: A Framework for Strategizing and Defining Project Objectives and Deliverables* (confirm author and publisher before citing).

## 1. Separate five terms

| Term | Definition for the plan | Example |
|---|---|---|
| Goal | Broad intended result | Expand cold-storage capacity |
| Objective | Specific, measurable, time-bound target | 40 tonnes of certified storage operating by month 9 |
| Scope boundary | What is in and out | Includes building and refrigeration; excludes transport fleet |
| Deliverable | Tangible output | Commissioned cold room with certificate |
| Acceptance criterion | Test that proves the deliverable is complete | Holds 2–4 °C for 72 hours under load; inspector sign-off |

## 2. Write a light charter for each major initiative

Purpose; scope boundaries; constraints (budget, time, regulation); stakeholders and approvers; reason for the project and link to the strategy.

## 3. Collect requirements and break down the work

- Gather requirements from the people who will use and approve the result; write them unambiguously.
- Break the work into deliverable-oriented components (a work breakdown structure), each with an owner, cost, and duration.
- Vague work packages produce vague costs and timelines; refine until each package can be priced.

## 4. Control changes

- Require a formal change request for any material change to scope, cost, time, or quality.
- Assess each request for impact, benefit, risk, cost, and quality effect.
- Communicate the decision and consequences to all affected stakeholders.
- Do not absorb scope change silently during execution.
- Name the events that trigger re-planning in the quarterly game plan.

Informal verbal agreements can expand expectations without funding; founder-led firms, grant-funded and lender-funded projects, and construction work especially need a written, light change process.

## 5. Validate deliverables, not activity

For each milestone ask: was the deliverable produced, was it within scope, and did the right stakeholder accept it? Record acceptance evidence.

## Pass criteria

- [ ] Milestones stated as deliverables with acceptance criteria, not only dates.
- [ ] Scope boundaries and dependencies stated for major initiatives.
- [ ] Work broken into priced, owned packages.
- [ ] Change-control steps and re-planning triggers defined where execution is complex.
