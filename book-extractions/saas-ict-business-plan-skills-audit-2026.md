# SaaS / ICT Business-Plan Skills Audit — 2026

**Purpose:** Hardening report for the business-plan-skills engine to make it world-class at producing **living business plans** for ICT companies and SaaS startups, with explicit Africa-context awareness and bankability discipline.

**Method:** Walked the entire skill catalogue (00→16 plus all `meta-*`) against the seven extracted SaaS / ICT books (Walling, Cotton, Mersch, Golding, van der Kooij × 2, Garbugli). Flagged duplicates against existing skills; identified gaps; specified new skills, enhancements, and reference templates.

**Verdict in one paragraph:** The engine has world-class strategy, pricing, sales-writing, digital-transformation, critical-thinking, and bankability infrastructure. It has near-zero SaaS-specific operating discipline. There is no unit-economics model, no cohort retention template, no MRR/ARR waterfall, no sales-capacity calculator, no SaaS valuation framework, no PLG-vs-sales-led decision logic, no multi-tenancy/architecture-as-business-model rigour, no living-plan operating cadence, no Africa-specific SaaS context file. This audit specifies the fix.

## Part 1 — NEW SKILLS to Create

Each entry: skill name → target folder → one-line description → why-needed → primary source.

### Section 10 — Financial Projections

1. **`saas-unit-economics-and-cohort-model`** → `skills/10-financial-projections/` — Build LTV, CAC, CAC payback, LTV:CAC, gross margin per cohort, NRR/GRR, magic number, Rule of 40, burn multiple, quick ratio. **Why:** the engine has no SaaS-specific financial model. **Source:** Mersch ch. 1–4; Cotton essays 1, 3, 4, 9; Walling pp. 130–160.

2. **`saas-mrr-arr-financial-modeling`** → `skills/10-financial-projections/` — Build the ARR waterfall (new + expansion − contraction − churn), bookings-vs-billings-vs-revenue-vs-cash, deferred-revenue schedule, working-capital-trough modelling. **Why:** standard P&L cannot represent SaaS. **Source:** Mersch ch. 2, 5–6.

3. **`saas-cohort-retention-modeling`** → `skills/10-financial-projections/` — Logo cohorts and revenue cohorts; retention curves; "smile" cohort; involuntary-churn cohort separation; cohort gross margin. **Why:** investors require this; engine has nothing. **Source:** Mersch ch. 11, Garbugli ch. 38.

### Section 07 — Marketing & Sales Strategy

4. **`saas-pricing-and-packaging-strategy`** → `skills/07-marketing-sales-strategy/` — Tiering, freemium, usage-based, hybrid, enterprise. Price-corridor analysis. Expansion-revenue dimension selection. Annual prepay discount. **Why:** existing `meta-pricing-strategy` is Kennedy-based (premium positioning); doesn't cover SaaS structural pricing. **Source:** Walling pp. 67–106; Mersch ch. 10; Cotton essay 6.

5. **`saas-gtm-motion-design`** → `skills/07-marketing-sales-strategy/` — PLG vs sales-led vs hybrid vs marketplace vs channel-partner decision. Maps motion to ACV, cycle, methodology. **Why:** GTM motion is the master determinant of org design and economics; engine has no framework. **Source:** van der Kooij AE volume; Walling cheat-codes chapter; Cotton essay 8.

6. **`saas-sales-org-design-and-capacity-planning`** → `skills/07-marketing-sales-strategy/` + cross-ref to `skills/09-management-team/` — Quota × attainment × ramp × headcount = bookings. Pod design. SDR:AE:CSM ratios. **Why:** plans projecting $5M ARR with 2 sales hires fail bankability scrutiny. **Source:** van der Kooij both volumes.

7. **`saas-customer-success-operating-model`** → `skills/07-marketing-sales-strategy/` and `skills/08-operations-plan/` — High-touch / mid-touch / tech-touch model. Health score. Onboarding-to-renewal lifecycle. Expansion playbook. **Why:** NRR engine sits in CS; engine has no CS skill. **Source:** Cotton essays 4, 9; Mersch ch. 7; Garbugli sequences 2-5.

8. **`saas-marketing-channel-economics`** → `skills/07-marketing-sales-strategy/` — Per-channel CAC, payback, scale ceiling. Content / SEO / paid / partnerships / community / events / WhatsApp. Marketing arbitrage discipline. **Why:** plans treat marketing as a budget number, not a channel-economics decision. **Source:** Cotton essays 6, 8; Walling pp. 107–135.

9. **`saas-lifecycle-email-and-retention`** → `skills/07-marketing-sales-strategy/` — Seven sequence families. Deliverability infrastructure. Behavioural segmentation. Cross-channel orchestration with WhatsApp. **Why:** highest under-utilised revenue lever in African SaaS. **Source:** Garbugli entirely.

## Part 4 — The "Living Document" Governance Pattern

Every new and enhanced skill in this audit must encode the **Living-Plan Operating Model**. Specifically each skill section must address:

- **Data feed** — which KPI / metric / signal feeds this section
- **Cadence** — weekly / monthly / quarterly / annual / trigger-based
- **Owner** — which role on the team maintains it
- **Decision log** — where decisions get recorded, with reasoning
- **Variance threshold** — at what plan-vs-actual variance the section gets re-planned
- **Sunset policy** — when content is archived as superseded

The cross-cutting reference `living-business-plan-operating-model.md` will codify this pattern once; new and enhanced skills will reference it rather than re-stating.
